# phonegyro-dump

*[Read in English](README.md)*

Минимальный инструмент проверки соответствия/диагностики для
[PhoneGyro Hardware Protocol](../../docs/PROTOCOL.ru.md). Открывает
serial-порт, декодирует поток кадров и печатает их в читаемом виде, плюс
статистику качества связи (кадров/сек, отброшенных байт мусора).

Обычный текстовый терминал (Serial Monitor в Arduino IDE, PuTTY и т.п.)
всегда покажет этот поток как нечитаемую бинарщину — протокол сознательно
бинарный, не текстовый. Используйте этот инструмент, когда нужно реально
прочитать значения или проверить, что устройство правильно реализует контракт.

## Сборка

```
cd tools/phonegyro-dump
go build -o phonegyro-dump.exe .
```

## Использование

```
phonegyro-dump <порт> [секунды]
```

- `<порт>`: например `COM3` на Windows, `/dev/ttyUSB0` на Linux.
- `[секунды]`: опционально; остановиться автоматически через N секунд. Без
  этого параметра работает до Ctrl+C.

Запуск без аргументов покажет список найденных serial-портов.

Исправное устройство должно выйти на стабильный поток с заявленной частотой
(200 Гц у референсной прошивки) с нулевым или почти нулевым количеством
мусорных байт. Несколько байт мусора ровно в момент открытия порта — это
нормально: бутлоадер Arduino перезагружает плату при подключении (сигнал
DTR), и декодер восстанавливается за пару байт. А вот если мусор продолжается
на протяжении всей записи — это уже реальная проблема (проводка, скорость
порта, питание).
