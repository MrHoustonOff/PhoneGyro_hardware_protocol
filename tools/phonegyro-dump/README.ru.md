# phonegyro-dump

*[Read in English](README.md)*

Минимальный инструмент проверки соответствия/диагностики для
[PhoneGyro Hardware Protocol](../../docs/PROTOCOL.ru.md). Открывает
serial-порт, декодирует поток кадров той же логикой ресинхронизации и
CRC-8, что и настоящий хост, и печатает:

- кадры в читаемом виде (метаданные и данные),
- живой чеклист pass/fail по требованиям самого протокола,
- статистику качества связи (кадров/сек, потерянные кадры, байты мусора).

Обычный текстовый терминал (Serial Monitor в Arduino IDE, PuTTY и т.п.)
всегда покажет этот поток как нечитаемую бинарщину — протокол сознательно
бинарный, не текстовый. Используйте этот инструмент, когда нужно реально
прочитать значения или проверить, что устройство правильно реализует контракт.

## Сборка

```
cd tools/phonegyro-dump
go build -o phonegyro-dump.exe .
```

## Использование

```
phonegyro-dump [порт] [секунды]
```

Оба аргумента опциональны:

- **Совсем без аргументов** (в том числе просто двойной клик по `.exe`):
  инструмент сам сканирует все serial-порты машины — тот же принцип
  автообнаружения, что и у настоящего хоста (Уровень 4 протокола), не нужно
  знать имя COM-порта заранее. Также всегда ждёт нажатия Enter перед
  закрытием окна, так что двойной клик никогда не мелькнёт и не исчезнет.
- `[порт]`: например `COM3` на Windows, `/dev/ttyUSB0` на Linux. Укажите,
  чтобы пропустить сканирование и подключиться к конкретному порту напрямую.
- `[секунды]`: используется только вместе с `[порт]`; остановиться
  автоматически через N секунд вместо работы до Ctrl+C. Удобно для
  скриптовых проверок.

## Как читать вывод

```
no port given -- scanning every serial port for a PhoneGyro device (protocol Level 4 auto-discovery)...
found a device on COM3
listening on COM3 at 115200 8N1 -- Ctrl+C to stop
[META]  protocol=1.0.0  accelRange=2g  gyroRange=250 deg/s  rate=200Hz  caps=0x00
[DATA]  seq= 40  ts_us=    200880  accel=(    -8, -8860, 14448)  gyro=(  -229,    53,    33)  temp= 3742  buttons=0x00
[CHECK] frames=OK  rate=OK (199 Hz)  metadata=OK  loss=OK  garbage(total)=16 bytes
```

- `[META]` — печатается один раз (и повторно только если реально
  изменится); показывает объявленную устройством версию протокола и
  диапазон датчиков.
- `[DATA]` — очередной кадр данных, показывается примерно 5 раз/сек, чтобы
  реальный поток на 200 Гц оставался читаемым; сырые значения регистров, не
  физические единицы.
- `[CHECK]` — вердикт pass/fail, обновляется каждые ~2 секунды и ещё раз в
  итоговой сводке:
  - `frames` — хоть один валидный кадр вообще был получен.
  - `rate` — измеренная частота не ниже минимума самого протокола (100 Гц).
  - `metadata` — реальный кадр метаданных был получен (`MISSING` значит,
    что применены безопасные дефолты — проверьте, что устройство его
    действительно отправляет).
  - `loss` — в счётчике SEQ нет пропусков (иначе `WARN (N dropped)`).
  - `garbage(total)` — байт отброшено при ресинхронизации, накопительно с
    начала запуска.

Немного мусора ровно в момент открытия порта — это нормально: открытие порта
часто перезагружает Arduino (сигнал DTR), и плата перезапускается посреди
кадра; декодер восстанавливается за пару байт. Устройства на протоколе v1.1
к тому же раз в секунду повторяют метаданные; `[META]` всё равно печатается
только при изменении. А вот если мусор или `loss`
продолжаются на протяжении всей записи — это уже реальная проблема
(проводка, скорость порта, питание).
